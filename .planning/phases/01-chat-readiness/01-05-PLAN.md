<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| replied Telegram message → durable identity | Nested `from` data may be absent, bot-owned, anonymous, or unrelated to typed command text. |
| roster command/callback → current administrator check | Listing and every mutation are protected actions with fresh external authorization. |
| opaque removal/page token → membership transaction | The token is untrusted; actor/chat/target/expiry authority is server-side. |
| durable identity → public Telegram projection | Names/usernames/IDs require privacy-preserving display and stable action mapping. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-01-18 | Spoofing | `/roster_add` target identity | high | mitigate | Accept only non-bot `reply_to_message.from`; never build membership from typed text or username. |
| T-01-19 | Tampering | removal callback replay/cross-target | high | mitigate | Opaque actor/chat/target/expiry-bound action, fresh authorization, one transaction, and single consumption. |

| T-01-22 | Denial of service | long roster projection | low | accept | Fixed deterministic pages of 20 bound message size and callback count for the small band-chat domain. |
