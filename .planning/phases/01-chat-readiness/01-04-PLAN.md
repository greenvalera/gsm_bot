<interfaces>
- `SettingsService.getCommitted(chatId)` returns a complete `ChatConfiguration` projection or a typed not-configured/read-failure result; it never returns a partial draft.
- `SettingsEditDraft` is unique per `(chatId, actorUserId)`, names exactly one editable field/value-pair, stores validated replacement payload, expected configuration revision, and 30-minute expiry.
- `SettingsService.saveChange` reauthorizes, consumes an actor-bound opaque action, validates the whole resulting configuration, compares revision, and commits exactly one new revision in a transaction.
- `canStartPlanning({ currentRole, policy, wasPreviousParticipant })` always allows current administrators and otherwise evaluates the selected broadening policy.
</interfaces>

## Trust Boundaries

| Boundary | Description |
|---|---|
| settings command/callback/input → authorization | Each continuation may be sent by a stale or different actor and requires a fresh role result. |
| SettingsEditDraft → ChatConfiguration | Draft value, revision, actor, and target field cross into active configuration only in one transaction. |
| committed configuration → Telegram dashboard | Partial reads or draft values must not be represented as authoritative settings. |
| policy value → Phase 2 authorization | An invalid or misinterpreted enum could broaden or narrow planning-start access. |

| T-01-14 | Tampering | stale settings write | high | mitigate | Actor-bound action, expected revision, full reconstructed-config validation, and one transaction prevent lost updates. |
