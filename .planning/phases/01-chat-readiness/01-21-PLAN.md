## Gap Closure Context

This plan closes the first half of **G-01-6 / finding F-4 / broken window 12**
(see `.planning/debug/no-update-path-logging.md`). F-4 is correctly filed as *unrun-verify* rather
than a deviation: 01-14 delivered exactly what it specified, and UAT test 6 asserted more.

Root cause — three simultaneously-necessary causes (AND-gate confirmed):

1. **STRUCTURAL.** `createLogger` is built at `main.ts:28` and is in lexical scope at the
   `createBot(...)` call on `:42-47` but is not passed. None of the three update-path dependency
   containers declares a logger member: `BotDependencies` (`create-bot.ts:22-29`),
   `ChatReadinessServices` (`handlers.ts:40-48`), `CallbackBoundaryDependencies`
   (`callbacks.ts:71-75`). No handler *can* log. `grep` for `logger` across `src/telegram`,
   `src/domain` and `src/infrastructure` exits 1; `grep` for console/stdout/stderr across all of
   `src/` returns zero hits, so pino inside `logger.ts` is the process's only stream writer.
2. **NEUTRALISED SEAM.** `bot.catch` (`main.ts:50-59`) is a genuine, reachable update-path seam that
   already logs an update identifier and a chat identifier under correct allow-listed keys, but 12
   bare catch blocks convert every exception into user-facing copy without binding the error, so it
   never fires. *(Closed by plan 01-22.)*
3. **VERIFICATION DESIGN.** 01-14 scoped the logging key link as composition-root-to-logger and its
   acceptance criterion as a redactor unit test; it never required emission. The coordinate grep is
   a universally-quantified claim over an empty set — vacuously true, and equally true if the
   redactor were entirely broken. Confirmed by execution: driving the exact F-3 scenario through the
   real callback boundary produced zero bytes on stdout and stderr. *(Closed by Task 3 here and the
   runbook correction in plan 01-22.)*

### Binding allow-list constraints (measured, from gap G-01-6)

- The redactor keeps 27 allow-listed fields and redacts everything else. **`timezone` is NOT
  allow-listed and yields the redaction placeholder.** Do not add it to the allow list — carry the
  fact of a resolution under `outcome`/`field`, never the resolved value.
- **An allow-listed key holding an OBJECT is redacted, not walked.** Pass identifiers as
  bigint, number or string only. bigint values are stringified.
- `err`/`error` yields name, message and code only; the stack is dropped by design, so an error must
  be BOUND in the catch to be loggable at all.
- `CHAT_READINESS_ROUTES` (`handlers.ts:65-129`) already defines a bounded id vocabulary that drops
  straight into the allow-listed `route` field.
