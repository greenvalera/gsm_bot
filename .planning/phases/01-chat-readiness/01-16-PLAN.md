## Gap Closure Context

This plan closes **G-01-17 / finding F-3 / broken window 4** — the phase blocker.

Root cause (already diagnosed, do NOT re-diagnose — see `.planning/debug/callback-alerts-never-shown.md`):
`src/telegram/callbacks.ts:111` answers every callback query unconditionally with an empty
payload before any parse, role lookup, or durable read. Telegram honours only the FIRST answer
per `callback_query.id` and silently discards later ones, so all 24 alert-bearing
`answerCallbackQuery({ text, show_alert })` calls in the codebase are second answers and are
dropped. The alert texts are correctly defined and correctly wired; the defect is purely ordering.

Escape cause (N-2): the e2e transport double at `tests/integration/chat-readiness.e2e.test.ts:99-121`
returns `ok:true` for a repeated answer and the boundary assertions at `:441-455` read the LAST
answer. The suite ratifies the defect. **The harness is hardened first (Task 1) so the regression
in Task 2 can fail for the right reason.**

**Ordering constraint (load-bearing):** this plan runs BEFORE plan 01-19 (F-2). Fixing F-3 alone
turns silence into an alert on a button that should not be on screen; fixing F-2 alone removes the
button. Both are needed, in that order.

<objective>
Make the single answer Telegram honours per callback query the one that carries the outcome, so
the four verbatim contract alert texts become reachable on every surface.

Purpose: Test 17 is a blocker. Four Copywriting Contract strings (stale setup action, stale
settings/roster action, callback permission denial per D-13, `Already applied.`) are defined,
wired, and unreachable. Every protected callback surface (setup, settings, roster) is affected.
Output: A single-shot acknowledgement guard on the callback boundary, a transport double that
models Telegram's one-answer rule, regression coverage for the stale and denial paths, and the
re-recorded phase decision this fix reinterprets.
</objective>
