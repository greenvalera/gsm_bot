# Quick 260922-uwu: /roster_add @username pending invites Summary

Administrators can now add a band member they cannot reply to: `/roster_add @username` either adds a member already stored in this chat or posts a durable, 7-day invite with an opaque `v1:<uuid>` Join button, and only the Telegram user whose username matches can press it to join. `/roster_add` with a text_mention adds that user directly. Membership is still created only from a real Telegram user ID.

## What was built

- **Schema and migration (D-08):** `RosterInvite` model (`roster_invites`, BIGINT chat/user ids, TIMESTAMPTZ(3) timestamps, unique `(chat_id, username)`) and `ROSTER_JOIN` appended last to `CallbackActionKind`. **Migration SQL source: generated by Prisma's differ** (`npx prisma migrate diff --from-schema <HEAD schema copy> --to-schema prisma/schema.prisma --script` with a dummy DATABASE_URL), not hand-written. Client regenerated with `npx prisma generate` (the generator also moved `NullableBigIntFieldUpdateOperationsInput` from `models/PlanningRound.ts` into shared input types, which is normal regeneration output).
- **Deploy preflight:** `prisma/migrate-deploy.mjs` has `ROSTER_INVITE_MIGRATION`, a `roster_invites` table catalog in physical column order, pkey + unique index, and the trailing `ROSTER_JOIN` label when the migration is applied.
- **Domain:** `normalizeTelegramUsername` (single source of truth), `ROSTER_INVITE_LIFETIME_MS` (7 days), extracted `upsertActiveMembership(tx, …)` shared by `addFromRepliedUser` and `acceptInvite`, `openInvite` (upsert + reopen consumed/expired row + one Join action per prompt), `acceptInvite` (stale / duplicate / wrong-user with no writes / guarded `updateMany` consumption + membership upsert in one transaction), `addByKnownUsername` (this chat only, exactly-one match).
- **Telegram:** new `src/telegram/roster-invite-handlers.ts` with `parseRosterAddArgument`, `handleRosterAddArgument` and `dispatchRosterJoinCallback`. `handleRosterAddCommand` calls the argument path only when there is no replied non-bot user; every existing reply expression is unchanged. `rosterInviteKeyboard`, `rosterJoinCallbackRoute`, the `callback:ROSTER_JOIN` route id, and Join registration in both the composed exhaustive table and the focused roster table.
- **Copy (D-06):** `roster.inviteButton`, `roster.invitePrompt`, `roster.inviteWrongUser`, `roster.inviteStale`, `roster.inviteNonMember` in en + uk; `roster.addUsage` updated in both languages to name both forms.
