<dst_policy>
**The recorded DST policy for this project. State it, do not re-derive it.**
(02-RESEARCH.md § Architecture Patterns / Pattern 2; closes the `STATE.md` concern.)

1. **Generation is civil.** Day lists and hourly slots are produced from the round's
   snapshotted minute-of-day values only. DST never changes which slots the containment
   rule admits.
2. **Skipped wall clock (spring forward)** -> the slot is **rendered and refused**,
   using the same unavailable marker and private alert as a past slot. One consistent
   unavailability rule across both selectors.
3. **Ambiguous wall clock (fall back)** -> resolves to the **earlier, pre-transition
   occurrence**; the slot is offered normally with no special marker. This matches the
   Temporal `"compatible"` disambiguation default.
4. **Duration is exact elapsed time.** `endsAt = startsAt + durationMinutes * 60_000`.
   A rehearsal spanning a fall-back transition is two real hours, not three wall-clock
   hours. This is the non-obvious half and it is deliberate.
5. **Civil values are authoritative; the instant is derived.** Persist `selectedDate`
   (`"YYYY-MM-DD"`), `selectedStartMinute`, the round's `timezone` snapshot, AND the
   derived `startsAt`/`endsAt` `timestamptz`. Display always renders from the civil pair
   — so a chat that later changes its timezone still shows the day the band agreed on —
   while ordering and past-ness use the instant, which is recomputable from the civil
   pair plus the zone.
6. **tzdata freshness is a deployment concern.** Node's bundled ICU carries the tz
   database, so a zone whose rules change is corrected only by a Node upgrade. It is not
   fixable in code; it is a recorded operational risk.

**Temporal is not available.** Verified on this runtime: `typeof Temporal` is
`undefined` on Node v24.18.0, and `package.json` pins `>=24.19 <25`. Temporal ships
unflagged only in Node 26. No time library is added — the resolver is ~40 lines of
`Intl.DateTimeFormat(...).formatToParts`, empirically verified against Europe/Kyiv,
America/New_York and Australia/Lord_Howe transitions including a 30-minute shift. This
also avoids a human dependency-approval gate, which Phase 1 precedent
(`tz-lookup` rejected, `geo-tz` approved only after a separate audit) makes expensive.
</dst_policy>
