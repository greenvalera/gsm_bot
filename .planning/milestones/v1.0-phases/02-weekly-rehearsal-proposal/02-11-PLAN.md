<objective>
Close the last two items in G-02-5: WR-09, the confirm lineup read that happens one
statement before the atomic gate under READ COMMITTED, and WR-05, the callback_actions
rows that are never reaped.

Purpose: `confirm()` reads the lineup through `listActiveMemberships(tx, chatId)` and
then writes that list as the participant snapshot several statements later. The doc
comment says the read is "inside the transaction", implying an atomicity that READ
COMMITTED does not provide — the read takes no lock, so a roster change committing
afterwards is invisible and the durable snapshot can disagree with the roster at
commit time. Phase 3 reads that snapshot to decide who may answer, so this is
cross-phase correctness, not tidiness. Separately, nothing in the codebase ever
deletes a callback_actions row: every `/plan`, every step transition and every
successful `/plan_status` mints a full step set, almost none are ever spent, and the
table grows for the life of the database behind a `findUnique` on every single
callback.

Output: a row-share lock taken before the lineup read and held to commit, proven from
the database catalog while the transaction is open; and a read-time retention sweep
with a window, chat scoping and failure tolerance, all covered.

Depends on 02-09 for the `callback_actions(expires_at)` index the sweep needs and the
participant foreign key, and on 02-10 for the racing-client helper this plan reuses to
observe the lock and for the token-release changes to the same service file.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Roster surface -> confirm transaction | A roster removal is an independent, concurrently committed write against the rows the confirm snapshot is built from. |
| Phase 2 snapshot -> Phase 3 authorization | The participant rows are the durable contract Phase 3 reads to decide who may answer. |
| Unbounded callback_actions -> every callback | The boundary performs a `findUnique` on this table for every single button press in the whole bot. |
