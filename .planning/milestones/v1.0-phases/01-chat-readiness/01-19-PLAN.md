## Gap Closure Context

This plan closes **G-01-18 / findings F-2 and F-9 / broken windows 8 and 11**
(see `.planning/debug/setup-wizard-card-not-replaced.md`).

**F-2 primary** — `replyWithStep` (`setup-handlers.ts:155-188`) types its ctx as `{ reply: … }` at
`:156` and therefore emits `sendMessage` at `:168` and `:182`; the narrow type makes an
`editMessageText` call a compile error, so the mistake was locked in at the signature. The correct
project pattern is the structurally identical `showReview`/`showPrompt`
(`settings-handlers.ts:97-130` / `:131-174`), typed `{ editMessageText: … }`, on the identical
`CallbackContext` type — proving no stored message id is needed on a callback path.

**F-9** — `SETUP_POLICY_BUTTONS` (`keyboards.ts:44-50`) maps all three policies into ONE declared
row, and `setupKeyboard` emits `.row()` only between declared rows, so the three share one keyboard
row at roughly a third of the card width each and Telegram truncates the 21-character middle label.
The row algorithm is correct; the declaration is the defect. Both correct patterns already exist in
the same file: `SETUP_WEEKDAY_BUTTONS` (`:24-34`) splits rows deliberately, and
`planningAccessKeyboard` (`:96-108`) calls `.row()` per button.

### Binding owner decision (2026-08-24) — do not re-open

**F-2 is scoped to the CALLBACK HALF ONLY.** Convert the three `replyWithStep` callback call sites
plus the two direct replies at `setup-handlers.ts:496` and `:525`. **Do NOT add
`SetupDraft.cardMessageId`. No Prisma migration in this wave.** The six text-input steps stay as
they are; that residual is filed as **N-6** backlog. The UI-SPEC clause is worded "after every
callback", which the callback-half fix satisfies.

**Ordering (load-bearing):** plan 01-16 (F-3) already landed. F-3 alone turned silence into an alert
on a button that should not be on screen; this plan removes the button. Both were needed, in that
order.

Escape cause (N-2): `chat-readiness.e2e.test.ts` `completeSetup` reads each next wizard card via
`lastOf("sendMessage")` (`:278`, `:291`, `:302`, and the save-token lookup at `:305-308`), and the
workflow test reads the committed card the same way. The gate does not merely miss F-2 — it encodes
it as the contract. F-9 was never gated at all.

<objective>
Make every button-driven setup transition replace its card in place and give the planning-access
step one button per row, then remove the spec ambiguity that let both survive review.

Purpose: The wizard appends a new card at every step and leaves the previous card's buttons live and
tappable — the origin of the 17 orphaned START_SETUP tokens observed in UAT test 17 — while settings
and roster replace correctly. Setup step 8 truncates a label because three buttons share one row.
Output: An edit-shaped step renderer for the callback half, three single-button policy rows with the
row-shape assertion that never existed, corrected e2e card lookups, and a UI-SPEC that can no longer
be read two ways.
</objective>
