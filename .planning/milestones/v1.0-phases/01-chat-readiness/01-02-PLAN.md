## Trust Boundaries

| Boundary | Description |
|---|---|
| Telegram update → grammY handler | Chat, actor, command, callback, and location data are untrusted and unordered. |
| grammY handler → Telegram membership API | Current administrator status is external authorization evidence and must be refreshed per action. |
| application service → PostgreSQL | Only validated, authorized state transitions may cross into durable storage. |
| approved package set → local lockfile/runtime | Only exact human-approved direct dependencies may enter executable code. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-01-03 | Spoofing | `/setup` actor authorization | high | mitigate | `createBot` calls live `getChatMember` for `chat.id` and `from.id` at every protected action and accepts only creator/administrator. |
| T-01-04 | Elevation of privilege | resumed setup draft | high | mitigate | Actor/chat uniqueness plus current-role revalidation precede every protected read or write; denial removes an identifiable actor draft. |
| T-01-05 | Tampering | callback/update payload | medium | mitigate | Validate update shape and opaque callback token before loading server-side action; authority never comes from callback text. |
| T-01-07 | Denial of service | duplicate/in-flight updates | low | accept | Chat-key sequentialization bounds local overlap; database uniqueness provides correctness for the small trusted group workload. |
| T-01-SC | Tampering | npm dependency install | high | mitigate | Install only the exact non-historical direct roots approved by Plan 01-15, require `geo-tz@8.1.8`, exclude rejected tz-lookup, and commit the resulting lockfile. |
