<objective>
Carry the new `BOOKED` lifecycle position through every query that already narrowed its result set with a hard-coded status literal (D-15), and make `/plan_status` a working recovery path for a round that has left the wizard (D-03).

Purpose: `WEEK_CLAIMING_STATUSES` is an *inner* filter. Three queries hand it a set they have already narrowed to confirmed rounds, so widening the constant alone changes nothing — and one of those three is an authorization filter. Two more queries only admit draft rounds, which makes D-03's recovery path unreachable. Five sites, five separate ways to ship a silent regression.
Output: a widened `WEEK_CLAIMING_STATUSES`, a new `RECOVERABLE_ROUND_STATUSES`, five individually-verified call-site changes, `loadAvailabilityActions` / `availabilityProjection` on `PlanningService`, a status-before-step branch in `renderStep` and `mintStepActions`, and extended real-PostgreSQL coverage in `planning-round.test.ts` and `planning-recovery.test.ts`.
